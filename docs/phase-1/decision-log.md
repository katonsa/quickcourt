# QuickCourt Phase 1 Decision Log

| ID       | Date       | Decision                                                                                                                         | Reason                                                                                                                                     | Impact                                                                                                       |
| -------- | ---------- | -------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| D-P1-001 | 2026-04-28 | Phase 1 includes technical foundation, identity/account foundation, and access foundation.                                       | Later marketplace features depend on reliable auth, DB, route guard, logging, and test foundations.                                        | Phase 1 produces usable protected shells, not booking/payment features.                                      |
| D-P1-002 | 2026-04-28 | Organization Phase 1 scope is plugin setup, route guard, access helpers, and seed/test organization only.                        | Current product docs place Super Admin create Organization and owner invitation in Milestone 2.                                            | No owner self-service organization creation and no invite UI in Phase 1.                                     |
| D-P1-003 | 2026-04-28 | Super Admin create Organization + invite owner remains Milestone 2.                                                              | Keeps Phase 1 focused and avoids pulling venue onboarding forward.                                                                         | P1 access code must support future invitation flow without implementing it.                                  |
| D-P1-004 | 2026-04-28 | Auth endpoint rate limiting is handled through Better Auth built-in `rateLimit`.                                                 | Avoid duplicate custom middleware for auth endpoints.                                                                                      | Custom app-level rate limiting is deferred for non-auth endpoints.                                           |
| D-P1-005 | 2026-04-28 | Resend is the transactional email provider for auth emails.                                                                      | Product docs already favor Resend/React Email for transactional email.                                                                     | Account recovery and email verification must use an email sender abstraction backed by Resend.               |
| D-P1-006 | 2026-04-28 | Because the final email domain is not ready, development supports console email fallback.                                        | Local development and test flows should not be blocked by domain verification.                                                             | Production must require `RESEND_API_KEY`, `EMAIL_FROM`, and verified sender domain.                          |
| D-P1-007 | 2026-04-28 | Engineering board statuses are `Todo`, `Ready`, `In Progress`, `In Review`, `Blocked`, `Done`.                                   | Makes docs useful as working implementation specs.                                                                                         | `breakdown.md` uses the status workflow.                                                                     |
| D-P1-008 | 2026-04-28 | Server env and client-safe env are split between `config/env.ts` and `config/public-env.ts`.                                     | Prevents accidental exposure of server secrets while keeping browser-safe values explicit.                                                 | Server-only modules import `config/env`; Client Components import only `config/public-env`.                  |
| D-P1-009 | 2026-04-28 | Pino is the Phase 1 structured logger with default redaction for secrets and high-risk PII.                                      | JSON logs and redaction are required before auth, booking, payment, and finance workflows exist.                                           | Server logging must use structured fields and avoid placing sensitive values in message text.                |
| D-P1-010 | 2026-04-28 | Baseline error pages show generic user-facing messages and server-side helpers handle error logging.                             | Users should not see stack traces, raw error messages, or internal implementation details.                                                 | Error boundaries stay safe for users; `lib/errors.ts` provides server-side normalization/logging.            |
| D-P1-011 | 2026-04-28 | `DATABASE_URL_TEST` is the canonical integration test database URL and must differ from `DATABASE_URL`.                          | P1-07 requires a DB integration harness that can exercise migrated schema safely without changing the app runtime datasource convention.    | Unit tests remain DB-free; DB-backed integration tests and test DB setup target `DATABASE_URL_TEST`.         |
| D-P1-012 | 2026-04-28 | P1-03 seed creates development/test sample organization membership but does not seed auth passwords.                             | Access tests need sample organization data, while Better Auth should own credential creation.                                              | Admin bootstrap is documented as an auth-aware user promotion path after P1-04 config exists.                |
| D-P1-013 | 2026-04-28 | PostgreSQL-specific constraints are isolated in the third migration and override Prisma's provisional `time_range` columns.      | Prisma cannot fully express generated `tstzrange` columns and exclusion constraints.                                                       | Review raw SQL migrations before changing booking-slot or availability-block constraints.                    |
| D-P1-014 | 2026-04-28 | P1-04 uses Better Auth's bundled `better-auth/adapters/prisma` export with the generated Prisma v7 client in `generated/prisma`. | The installed `better-auth@1.6.9` package exports the Prisma adapter path used by current docs, so no extra adapter dependency is needed.  | Runtime auth continues to use `lib/db.ts`; auth schema remains owned by the existing P1-03 migration.        |
| D-P1-015 | 2026-04-28 | Better Auth organization creation is disabled for ordinary users in Phase 1.                                                     | Product access rules require venue owner status to be granted through admin-controlled organization membership, not self-service creation. | P1-04 config enables the Organization Plugin without adding organization creation UI or owner invitation UI. |
